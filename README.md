# Удачный посёлок

Главная страница на Next.js. Для локального предпросмотра нужен Node.js 22 и команды `npm ci`, `npm run dev`.

Вопросы к заказчику, расхождения в макетах и данных, недостающие материалы и подключения собраны в [общем списке уточнений](docs/clarifications.md). Новые вопросы добавляем в этот файл; решения и даты сохраняем рядом с пунктами.

Статическая версия для GitHub Pages:

```sh
PAGES_PREVIEW=1 NEXT_PUBLIC_BASE_PATH=/udachny-poselok PREVIEW_URL=https://katysfreel.github.io npm run build
```

Готовые файлы будут в `out/`. Готовые файлы публикуются в корне ветки `gh-pages` репозитория `KatySFreel/udachny-poselok` с файлом `.nojekyll`. На статическом предпросмотре формы имитируют отправку, а поисковым роботам передаётся `noindex`.

Для основного сайта задайте `SITE_URL` с финальным адресом и используйте обычную серверную сборку `npm run build`. Канонический адрес и карта сайта будут строиться из `SITE_URL`. Пока включён общий переключатель «Тест форм», формы и квиз имитируют отправку. Для подключения квиза предусмотрена серверная переменная `QUIZ_WEBHOOK_URL`. Перед индексацией нужно завершить внутренние страницы и подключить реальную отправку форм.

## Проверка перед публикацией

- Проверена статическая сборка в подпапке на ширинах 375 и 1512 px. Изображения, стили, фавиконка и тестовый квиз загружаются, у главной один H1, у всех `img` есть атрибут `alt`.
- Для фотографий домов и посёлков добавлены описания, декоративные изображения сохраняют пустой `alt`. Две пары идентичных SVG сведены к общим файлам.
- На первом экране используются разные WebP для телефона и настольного экрана, изображения ниже загружаются по мере приближения к ним. Локальные замеры объёма ресурсов — ориентир для предпросмотра, Core Web Vitals стоит измерять после запуска основного домена.
- До индексации нужно добавить страницы, на которые ведут внутренние ссылки главной, настроить формы и проверить метаданные, sitemap и доступность страниц уже на основном домене.

## Локальный шаблон страницы посёлка

Страница: `/poselki/troitskaya-sloboda`. Публикация разрешена Екатериной 28.11.2026 в запросе отправить изменения и опубликовать все страницы.

Шаблон находится в `components/settlement-page.tsx`, сериализуемое содержимое — в `content/settlement-pages.ts`. Для следующего посёлка добавляется объект `SettlementPageData`; маршрут генерируется из его `slug`. Будущая админка сможет отдавать тот же формат через замену `getSettlementPage`, без копирования вёрстки.

Генплан использует координаты исходного изображения и отдельный массив участков: стабильный `id`, номер, контур, площадь, цена и статус. Из обновлённого фрейма `4118:27040` перенесён 231 контур на аэрофотографии: 44 участка в продаже и 187 проданных по состояниям макета. Коммерческие параметры сохранены у 17 ранее известных участков, недостающие значения не выдуманы. Контуры и подписи, включая повторяющиеся номера из макета, имеют разные стабильные ID. Фильтры применяются к данным, выбор работает мышью и клавиатурой, есть масштабирование и полный экран. В обоих режимах генплан перемещается зажатой мышью, колесо прокручивает страницу, масштаб меняется кнопками. Полосы прокрутки скрыты; на сенсорном экране сохраняется перемещение жестом.

Формы используют общий режим имитации отправки. Для генпланов работает локальная админка `/admin/genplany`: пароль, сохранение на сервере, редактирование данных участков и очередей, импорт и экспорт JSON. Инструкция — [docs/plan-admin.md](docs/plan-admin.md). Реальная отправка заявок пока не подключена. Для видео предусмотрен `videoUrl` (до заполнения открывается существующий канал компании), для PDF — `presentationUrl`.

Блок окружения Троицкой Слободы использует локальное изображение `public/images/settlements/troitskaya-sloboda/surroundings-map.svg`: геометрия OpenStreetMap, светло-голубая вода, мягкие оливковые леса, бежевый фон и светлые дороги из палитры карты главной. Метки берут общие `marker`, `pin`, `markerLabel` и иконку `home.svg` из компонента главной. Близкие объекты объединяются в одну метку со счётчиком и раскрывающимся списком; стрелок, выносок и соединительных линий нет. Метки, категории, карточки, увеличение и перемещение реализованы в React/CSS без картографического SDK, API и запросов к сторонним сервисам при открытии страницы. На телефоне карта прокручивается жестом, мышью её можно перетаскивать. Внешняя карта открывается только после нажатия на ссылку маршрута или источника.

Карточка Троицкой Слободы открыта по умолчанию и выделяет её метку. Фото, район, цена и кнопки маршрутов используют общий с главной `MapSettlementCard`. На странице посёлка карточка расположена над меткой, без указателя и стрелки; её можно закрыть и открыть снова. Переключение категории закрывает карточку, кнопка возврата к посёлку снова открывает её. Полосы прокрутки карты скрыты: на десктопе перемещение — зажатой мышью, колесо прокручивает страницу; на сенсорном экране сохраняется перемещение жестом.

Данные — локальный снимок OpenStreetMap от 22.11.2026 в `content/troitskaya-surroundings.json`: два медицинских объекта, два образовательных, четыре магазина, одна природоохранная территория и пять ближайших крупных лесных массивов, до 6 км от посёлка. Набор не является полным справочником инфраструктуры. Обновление данных вручную: `python3 scripts/update-settlement-surroundings.py`; поле `source` хранит исходный запрос. Границы и размер изображения находятся в `content/troitskaya-map-image.json`; координаты меток проецируются на него через `lib/static-map.ts`. Генерация фона из выгруженной геометрии: `python3 scripts/render-settlement-map.py --input area-*.osm` (скрипт работает без сети). При расширении территории нужно заменить фон и обновить его границы. Подпись OpenStreetMap сохранена. Для посёлков без набора объектов остаётся иллюстрированный компонент `HomeSettlementsMapBoard`; карта на главной сохранена.

Страница использует общие с главной переменные адаптации, `PageMotion`, `RoundLink`, `PaymentCard`, `SectionHeading`, `CarouselControls`, формы и карточки посёлков. Общий `useLoopingCarousel` обслуживает отзывы и фотогалерею; фотографии переключаются каждые 3 секунды по кругу, без открытия попапа. При системном уменьшении движения автопрокрутка и вращение отключаются.

## Страница «О компании»

Локальный маршрут: `/o-kompanii`. Карта адаптивов и измерения исходных фреймов — `docs/about-responsive-map.json`; происхождение новых изображений — `docs/about-assets.json`. Ссылка, подписанная в задании «1024», фактически ведёт на макет шириной 1440 px. Для диапазона 1024–1280 px используется компактная композиция с общими переменными адаптации проекта.

Услуги показываются строками на десктопе и аккордеоном ниже 1024 px. Карточки команды раскрываются при наведении или выборе; на планшете и телефоне ряд прокручивается до краёв секции. Карточки проектов располагаются одна под другой ниже 1024 px, а ниже 768 px содержимое каждой карточки тоже перестраивается в одну колонку. Общая форма экскурсии открывает общее окно «Спасибо!». В формах с полями в строку место под ошибки зарезервировано; при расположении полей в столбик пустого места нет, ошибки появляются в потоке. Правило одинаково на всех страницах и в попапах.

## Источники заявок

Все формы используют общий контракт источника: страница, форма, кнопка, блок страницы; формы посёлка также передают посёлок, а запись из генплана — ID и номер участка. Обычные и полноэкранные карточки участков открывают общую форму просмотра напрямую. Контракт payload, список подключённых форм и событий, тестовый режим описаны в [docs/lead-attribution.md](docs/lead-attribution.md). Реальная отправка обычных форм и подключение счётчика пока не настроены.

Общие `RequestDialog` и `InlineRequestForm` отвечают за формы и окно «Спасибо!». `PersonalDataConsent` используется обычными формами и квизом, `FilterChips` — фильтрами посёлков, домов и блога. Ссылки маршрутов обеих карт создаёт `mapRoutes`. Логику выбора и содержимое разных блоков сохраняем в их компонентах.

## Общая структура страниц

Все страницы подключают `SitePage`: он сохраняет общую шапку, основную область, анимацию появления и футер. Повторяющиеся блоки фотографии с формой используют `PhotoFormPanel`. Общие элементы карт, галерей, кнопок и карточек перечислены вместе с проверками в [аудите переиспользования](docs/code-reuse-audit.md).

## Правила адаптива и приёмки

Единая шкала ширин, сохранение карточек, пропорции изображений и порядок проверки зафиксированы в [docs/responsive-rules.md](docs/responsive-rules.md) и `AGENTS.md`. На 1440 px применяется широкая композиция 1920, компактная — только на 1024–1280 px. `npm run check:responsive` проверяет правила CSS и автоматически выполняется в `npm run build`.

## Админка сайта

`/admin/stranitsy` — страницы, общие блоки, черновики и публикации. `/admin/dostupy` — заявки пользователей, роли и подтверждение доступа. Генпланы остаются на `/admin/genplany`. Инструкция и требования к хранению: [docs/site-admin.md](docs/site-admin.md). Проверки: `npm run test:admin` и `npm run test:plans`.
