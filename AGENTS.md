# Горизонтальная прокрутка

Область прокрутки табов, слайдеров и горизонтальных списков доводи до краёв секции. Отступы сетки размещай внутри прокручиваемого ряда перед первым элементом и после последнего, чтобы при прокрутке элементы уходили за край секции без пустых полос по бокам.

# Адаптив: обязательные правила

- Ширину проверяй по `window.innerWidth` в CSS-пикселях, а не по физическому размеру экрана или скриншота. Учитывай масштаб браузера и боковые панели.
- Выше 1280 px сохраняй композицию 1920 и масштаб главной. Компактный макет, нарисованный в Figma на 1440 px, применяется только в диапазоне 1024–1280 px. На ширине браузера 1440 px должна быть композиция 1920.
- Диапазоны едины: `width > 1280px` — широкий десктоп; `1024px <= width <= 1280px` — компактный десктоп; `768px <= width < 1024px` — планшет; `width < 768px` — мобильный. Не добавляй переключения композиций на 1500, 1700 и других произвольных ширинах.
- Карточки, этапы и переходы в каталог нельзя скрывать через `nth-child`, `last-child` или другие CSS-правила ради заполнения ряда. На узком экране переноси их в следующий ряд или делай доступный горизонтальный список. Фильтрация, вкладки, раскрытие и скрытые дубли каруселей допускаются как явное состояние интерфейса.
- Сохраняй соотношение сторон слота изображения из макета. Не меняй ширину независимо от фиксированной высоты. Для карточек просмотра фотографии квадратные на всех ширинах, подпись расположена поверх фотографии. Кадрирование выполняй через `object-fit: cover`, без растяжения изображения.
- Повторяемые блоки меняй через общий компонент/стиль, включая форму с фотографией, карточки, фильтры и галереи. Полные правила и допустимые исключения: `docs/responsive-rules.md`.
- Перед сдачей проверяй все затронутые страницы, число доступных карточек и переходы на границах 767/768, 1023/1024, 1280/1281, а также 375, 1440, 1512 и 1920 px. Сверяй с нужным фреймом Figma при той же ширине; сохранение ошибочной старой вёрстки не считается проверкой макета.
- Запускай `npm run check:responsive`; эта проверка включена в `npm run build`. Новые исключения сначала обоснуй по макету и согласованным правилам.

# Общие компоненты

Адаптив всех страниц строится на правилах главной: общих `--section-unit`, `--section-layout-unit`, `--section-heading-size`, `--section-spacing`, отступах контейнера и компактном десктопном масштабе. Не заменяй их отдельной шкалой размеров для новой страницы. Композицию и акцидентную типографику сохраняй по макету, а повторяемые блоки, формы и кнопки подключай через общие компоненты и стили.

Если новый макет требует отличий, сверяй их с правилами общего компонента. Меняй его через общий стиль или явный вариант компонента.

Поведение ошибок общей формы зависит от расположения полей, а не от страницы: когда поля стоят в строку, резервируй место под ошибки; когда поля стоят друг под другом, не добавляй пустых отступов для ошибок. В вертикальной форме ошибки появляются в потоке, увеличение высоты допустимо. Применяй это правило и на мобильном, и на десктопе, включая попапы. Не добавляй отдельные флаги резервирования на страницах. Проверяй обычное состояние, валидацию и перестроение формы между ширинами.

Исключение по прямому запросу Екатерины: в финальной форме квиза не резервируй место под ошибки. В обычном состоянии сохраняй отступы макета; ошибки выводи в потоке под полями, увеличение высоты формы при валидации допустимо.

При добавлении общей формы на другую страницу сохраняй её согласованное поведение: после успешной отправки открывай общее окно «Спасибо!». Не заменяй его текстом внутри формы или отдельным сценарием для страницы без явного согласования с Екатериной. Проверяй успешную отправку, повторную отправку после закрытия попапа и ошибку отправки на каждой странице, где подключаешь или меняешь форму, на десктопе и мобильном.

Во всех телефонных полях используется только российский номер +7. Не добавляй стрелку возле флага и выбор страны, даже если они показаны в макете Figma.

Все формы подключай через общий контракт `LeadFormDefinition`, а кнопки входа — через `leadTrigger`: заявка должна содержать текущую страницу, форму, кнопку и блок страницы. Из генплана передавай ID и номер выбранного участка; открытие формы другой кнопкой не должно сохранять прежний участок. Используй общие `RequestDialog` и `InlineRequestForm`, события и поля атрибуции не дублируй на страницах. Тестовые отправки помечай `test`; контактные данные не передавай в события аналитики. Контракт описан в `docs/lead-attribution.md`.

Карту окружения посёлка делай на локальном изображении с интерактивными метками и фильтрами. Ориентир стиля — карта главной: её палитра фона, воды и лесов, общие стили меток и существующая иконка. Не заменяй стиль простой бежевой перекраской. Не добавляй стрелки, выноски и соединительные линии; близкие объекты объединяй в метку со списком. По запросу Екатерины не подключай сторонние картографические SDK, API и загрузку тайлов при открытии страницы. Ссылки для построения маршрута открываются только по нажатию пользователя.

Исключение для карты офиса по прямому запросу Екатерины от 23.11.2026: на странице `/kontakty` использовать встроенную карту Яндекса через iframe с отложенной загрузкой. Это разрешение не распространяется на карты окружения посёлков и общую карту в футере.

# Сверка с Figma

Бери за референс файл Figma, указанный для текущей задачи. При проверке размеров сравнивай один и тот же экран или попап при одинаковой ширине видимой области. Для десктопных попапов проверяй также промежуточную ширину 1512 px.
