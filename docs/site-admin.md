# Управление сайтом

Локальный адрес: `/admin/stranitsy`. Существующий редактор участков остаётся на `/admin/genplany`, пользователи — `/admin/dostupy`. Изменения не отправляются в GitHub. Публикация в редакторе обновляет содержимое работающего локального сервера, а не выкладывает проект в интернет.

## Страницы и контент

Слева находятся страницы, посёлки и общие блоки. Поля сгруппированы по блокам, есть поиск страниц и полей. Редактируются существующие тексты, ссылки, цены и характеристики карточек, фотографии, галереи и SEO. Общие контакты и навигация редактируются в одном разделе. Макеты и программное поведение форм остаются компонентами проекта; создание новых маршрутов, изменение структуры секций и количества карточек требует разработки. Квиз и технические состояния форм не являются свободным конструктором.

«Сохранить черновик» не меняет публичный сайт. «Предпросмотр» открывает сохранённый черновик и показывает специальную полосу; черновик доступен только вошедшему администратору, редактору или наблюдателю. На обычном адресе посетители получают опубликованную версию. «Опубликовать» доступно администратору и требует подтверждения со списком изменённых полей. История хранит 20 предыдущих публикаций; восстановление загружает выбранную версию в редактор для проверки и сохранения.

При конфликте версий запись отклоняется, правки остаются в редакторе. Скопируйте нужные значения и загрузите свежую версию. Перед переходом к другой странице редактор предупреждает о несохранённых правках.

Новые фотографии: JPG, PNG, WebP до 10 МБ. Файлы сохраняются в закрытом каталоге хранения и выдаются через `/admin-media/<случайное имя>`. SVG-загрузки не разрешены; исходные локальные SVG из проекта можно выбирать путём. Неиспользованные загрузки автоматически не удаляются. Кадрирование и пропорции слотов сохраняются в компонентах.

## Доступ

Сотрудник нажимает «Запросить доступ», указывает имя, рабочую почту и пароль не короче 12 символов. Почта служит логином, письма и коды не отправляются. До одобрения войти нельзя. Администратор видит заявку, выбирает роль и подтверждает выдачу доступа в отдельном окне.

| Роль | Возможности |
| --- | --- |
| Администратор | Пользователи, публикация страниц, черновики, генпланы |
| Редактор | Просмотр страниц, подготовка и сохранение черновиков |
| Менеджер участков | Редактирование и сохранение генпланов |
| Наблюдатель | Просмотр страниц, черновиков и генпланов без сохранения |

Изменение роли, отклонение заявки или отзыв доступа завершает все сеансы пользователя. Права проверяются на сервере при каждой операции. Владелец не редактируется через список пользователей; администратор не может изменить собственный доступ.

Владелец входит под логином `admin`. Пароль берётся из `ADMIN_OWNER_PASSWORD`, а при её отсутствии — из существующей `PLAN_ADMIN_PASSWORD`. Новый секрет в исходный код не записывается. Для плавного перехода ранее выданная подписанная сессия владельца генпланов принимается до её истечения. Новые именные сеансы хранятся на сервере и действуют 8 часов; браузер получает случайный токен в HttpOnly-cookie с SameSite=Strict. Пароли сотрудников хешируются scrypt с индивидуальной солью. После 10 неверных входов логин блокируется на 15 минут; блокировка сохраняется на диск.

## Хранение и развёртывание

По умолчанию `.data/admin/`: `access.json` — пользователи, хеши, сеансы и ограничения входа; `content-<id>.json` — черновик, публикация, версия и история; `media/` — загруженные изображения. Можно указать `ADMIN_DATA_DIR`. Каталог исключён из Git. Генпланы продолжают храниться отдельно по прежнему контракту `PLAN_DATA_DIR`.

Нужен один экземпляр Next.js, Node.js 22+ и постоянный диск с резервным копированием всего `.data`. Запись атомарная, параллельные операции сериализованы в процессе; ревизии защищают от перезаписи устаревшей копией. Несколько экземпляров или serverless требуют общей базы с транзакциями и объектного хранилища изображений. Отправка на GitHub не переносит данные из `.data`.

Публичные страницы получают опубликованные поля на сервере и передают их в общий `CmsProvider`. Черновики и данные пользователей в публичный HTML не включаются. Каталог полей `content/cms-catalog.json` задаёт разрешённые поля; неизвестные ключи, недопустимые ссылки, размеры и пути отклоняются. Ключи сохраняются при изменении исходных текстов; новые поля добавляются в каталог вместе с привязкой в компоненте.

Статический режим `PAGES_PREVIEW=1` использует исходное содержимое без локальных публикаций и серверных сеансов. В нём админка показывает, что редактирование доступно в серверной версии. Для рабочего редактирования требуется серверная сборка.

## Проверки

`npm run test:admin` проверяет черновики, публикацию, историю, конфликты, валидацию, ожидание одобрения, ограничения ролей, отзыв сеансов, выход и блокировку входа. `npm run test:plans` проверяет сохранение генпланов. `npm run build` включает проверку адаптивных правил и TypeScript.

Браузерная проверка: 20 публичных страниц и 3 раздела админки на ширинах 375, 767, 768, 1023, 1024, 1280, 1281, 1440, 1512 и 1920 CSS-пикселей. Проверены отсутствие горизонтального переполнения, заголовки и неизменность числа карточек; визуально проверены редактор на десктопе и мобильном, форма запроса доступа и список ролей. Пройдены сохранение черновика, отличие обычной страницы от предпросмотра, подтверждение публикации и обновление публичного текста. Тестовые правки и их история удалены, исходное содержимое восстановлено. Ошибок в консоли браузера не обнаружено.
