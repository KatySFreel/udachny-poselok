# Источник заявки

Единый контракт описан в `lib/lead-attribution.ts`. Общая форма и квиз добавляют JSON-поле `attribution` в `FormData` перед валидацией и отправкой. Серверная отправка квиза включает проверенное поле в webhook. Обычные формы пока имитируют отправку: подключение CRM/почты и счётчика аналитики остаётся отдельным этапом.

В `attribution`:

| Поле | Значение |
|---|---|
| `pagePath`, `pageTitle` | Текущая страница без query-параметров и якоря, её заголовок |
| `id`, `name`, `requestType` | Стабильный ID формы, её название и тип заявки |
| `buttonId`, `buttonLabel`, `placement` | ID и текст кнопки входа, блок страницы |
| `settlementSlug`, `settlementName` | Посёлок для просмотра и презентации |
| `plotId`, `plotNumber` | Участок из карточки генплана, включая переход через выбор очного или онлайн-просмотра |

По запросу Екатерины от 26 ноября 2026 года «Записаться на экскурсию» в генплане прокручивает страницу к секции «Запись на просмотр» без открытия формы. Выбранный участок передаётся обеим кнопкам секции через общий `leadTrigger`: исходная кнопка использует третий аргумент `{deferTo: slug}`, кнопки очного и онлайн-просмотра — `{continueFrom: slug}`. Контекст хранится в памяти только для текущей страницы; другая кнопка формы сбрасывает его. У события заявки остаются ID и подпись фактически нажатой кнопки в секции просмотров (`placement: visits`). «Узнать условия бронирования» по-прежнему открывает общую форму напрямую. Другие кнопки этой формы заменяют источник целиком, без старого участка. Повторная отправка сохраняет источник текущего открытия. Если посетитель самостоятельно дошёл до встроенной формы, источником считается её кнопка отправки (`placement: form`). Кнопки на первых экранах сертификата, рассрочки и инвестиций учитываются отдельно.

Сейчас подключены формы страниц проекта: консультация в десктопной шапке и мобильном меню, экскурсия на главной и странице компании, квиз на главной, сертификат, расчёт рассрочки и ипотеки, встреча по инвестициям, очный и онлайн-просмотр, презентация посёлка. На странице `/kontakty` обратный звонок имеет ID `contacts-callback`, а мобильная запись на экскурсию — `contacts-excursion`, согласно разному содержанию макетов. Для добавления формы обязательна `LeadFormDefinition`; для новой кнопки используется `leadTrigger(formId, {buttonId, buttonLabel, placement, ...})`. Не определять источник по тексту кнопки или CSS-классам.

## События

Общий адаптер отправляет объект в `window.dataLayer` и событие `site:lead` с тем же `detail`:

```json
{
  "event": "lead_form",
  "action": "form_success",
  "mode": "test",
  "attribution": {
    "pagePath": "/poselki/troitskaya-sloboda",
    "pageTitle": "Троицкая Слобода — Удачный посёлок",
    "id": "troitskaya-sloboda-visit",
    "name": "Запись на просмотр",
    "requestType": "visit",
    "buttonId": "plan-visit",
    "buttonLabel": "Записаться на просмотр",
    "placement": "plan",
    "settlementSlug": "troitskaya-sloboda",
    "settlementName": "Троицкая Слобода",
    "plotId": "troitskaya-2557",
    "plotNumber": "2557"
  }
}
```

Действия: `form_open` (открытие попапа), `form_start` (первое взаимодействие с формой), `form_validation_error`, `form_submit`, `form_success`, `form_error`. Конверсия — только `form_success` с `mode: live`. Симуляция помечается `test` и не должна засчитываться как реальная заявка. Контактные значения и ответы квиза в события не попадают. Пока счётчик не подключён, события доступны локально; запросов к сервису аналитики нет.

Серверный `readLeadAttribution` проверяет размер и обязательные поля, пропускает только перечисленные ключи. Эти сведения служат атрибуции: коммерческие параметры участка сервер должен брать из своей базы.
